# HM 运营工作台本地化设计

## 目标

将妙搭中的“电商运营数据工作台”V9 复制为 Mac 本地独立 Git 项目，在不影响妙搭线上版本和原始飞书多维表的前提下完成 UI/UX、AI 分析和受控写回能力的测试与调整。验收后的稳定版本再选择性回迁妙搭。

## 已确认边界

- 妙搭当前线上版本继续保留，作为对照和可用备份。
- 本地项目拥有独立 Git 历史，不依赖妙搭对话完成日常开发。
- 第一阶段只连接现有多维表副本，禁止写入原始业务表。
- AI 结论、任务创建和写回先使用测试表或本地模拟接口。
- 未经单独确认，不在妙搭执行代码修改、发布、任务创建或权限变更。
- 不把妙搭预览地址中的临时登录令牌、Cookie、密钥或 `.env` 凭据提交到 Git。

## 源码取得方案

优先从妙搭项目的现有 Git 远端取得完整仓库和提交历史。如果妙搭不提供可在本机使用的 Git 凭据，则使用平台的源码导出功能下载完整项目，再在本地初始化新的 Git 历史。

源码复制完成后保留妙搭原有目录结构和运行方式，先验证当前 V9 能在本地复现，再进行重构。不会使用线上页面抓取或单个 HTML 文件代替完整源码。

## 本地项目结构

```text
hm-operations-workbench/
├── client/                 # 当前工作台前端
├── server/                 # 本地接口与 AI 编排
├── shared/                 # 指标、任务、洞察等共享类型
├── sync/                   # 多维表只读同步适配器
├── tests/                  # 关键口径和写回保护测试
├── docs/                   # 设计、字段映射和回迁说明
├── .env.example            # 仅变量名称和说明
└── .gitignore              # 凭据、缓存、日志和导出数据排除规则
```

以实际导出的项目结构为准；若目录已有对应实现，延续现有结构，不重复建立平行模块。

## 分阶段实施

### 阶段 1：完整复现

- 取得完整源码和依赖清单。
- 建立独立本地 Git 仓库与初始基线提交。
- 安装依赖并启动本地预览。
- 对照妙搭 V9 检查导航、核心数据、诊断、待办、弹窗和主题。
- 记录需要平台环境才能运行的 SDK、接口和权限能力。

阶段 1 的完成标准是：本地页面可启动，主要页面可访问，已知平台依赖均有明确记录；不要求 AI 和写回已经接通。

### 阶段 2：数据安全层

- 将三份已接入多维表登记为只读数据源。
- 建立字段映射、数据时间、缺失值和口径校验。
- 将真实同步数据、测试数据和演示数据在界面中明确标识。
- 使用本地缓存或测试副本支持离线开发。

### 阶段 3：AI 洞察

- 将选定范围的数据整理为稳定的分析输入。
- 先执行确定性指标计算和异常检测，再调用大模型生成解释。
- 每条洞察保存结论、影响、证据、判断边界、建议动作和核验指标。
- AI 输出默认只读，不直接修改经营数据或创建正式任务。

### 阶段 4：受控任务写回

- AI 建议只能生成任务草稿。
- 用户确认后才写入专用测试表。
- 增加重复任务检测、幂等键、写回日志和失败重试。
- 通过测试后，再单独评估正式任务表、负责人消息和权限接入。

### 阶段 5：回迁妙搭

- 对比本地版本与妙搭运行环境差异。
- 仅迁移已验证的功能和依赖。
- 在独立预览或新版本中验收，不直接覆盖当前稳定版本。
- 明确回滚版本后再发布。

## 数据流

```text
飞书多维表副本
  → 只读同步与字段校验
  → 确定性指标计算
  → AI 洞察生成
  → 人工确认
  → 测试任务表写回
  → 执行回执与效果复盘
```

## 失败与安全处理

- 数据源不可用时显示最后成功同步时间，不以旧数据冒充实时数据。
- 缺失字段、缺少比较期或口径不一致时停止对应分析并显示原因。
- AI 调用失败不影响基础报表和确定性指标展示。
- 写回失败时保留草稿和请求记录，不自动重复创建任务。
- 日志不得记录访问令牌、Cookie、完整 `.env` 内容或敏感业务数据快照。

## 验证范围

- 本地构建和启动检查。
- 主要导航、筛选、弹窗和跨页状态检查。
- 核心指标计算、缺失值和比较周期测试。
- 真实、演示、测试数据标识检查。
- AI 输出结构和证据引用检查。
- 测试表写回、重复提交和失败恢复检查。
- Git 凭据与生成文件泄漏检查。

## 首轮不做

- 不修改原始业务多维表。
- 不启用正式负责人消息通知。
- 不把演示身份当作企业权限系统。
- 不立即重做全部视觉样式。
- 不直接覆盖或发布妙搭线上版本。

## 成功标准

- 本地版本能够独立启动和提交 Git，不依赖妙搭 AI 反复开发。
- 现有 V9 主流程和数据口径得到保留。
- 用户能从经营数据获得可核验的 AI 结论和任务草稿。
- 所有写回均可追踪、可重试、可避免重复，并在人工确认后发生。
- 回迁妙搭前具有清晰的变更清单、环境差异和回滚方案。
