# 待办事项与飞书多维表格读取更新闭环设计

## 1. 目标

第一阶段只完成“待办事项”模块与飞书任务多维表格之间的真实读取和更新闭环：

1. 用户通过飞书真实身份登录本地工作台。
2. 工作台读取“工作日报任务”表中的真实任务。
3. 用户在待办事项页面修改任务状态或负责人。
4. 本地服务将变更写回同一条多维表格记录。
5. 写入后清除缓存并重新读取源表。
6. 只有读回值与提交值一致时，界面才显示“已同步”。

本阶段不建设完整的经营分析、AI 建议或跨模块工作流，先验证最小任务模型能够稳定运行。

## 2. 使用者与权限

- 主要使用者：店铺运营人员。
- 辅助使用者：数据分析人员。
- 未登录用户可以查看任务，但不能提交修改。
- 第一阶段不区分管理员和普通运营人员。所有成功登录飞书的用户均可修改任意现有任务的状态和负责人。
- 后续如需限制为“只能修改自己的任务”或增加管理员角色，应作为独立权限阶段设计。

## 3. 唯一数据源

任务数据以以下飞书多维表格为唯一真实来源：

- Base token：`O4XhbiUw2aa5yRsgR8fckrNpnXe`
- Table ID：`tbl1Hi7UvvXTzTiQ`
- 表名：`工作日报任务`

工作台不复制一套可独立修改的任务主数据，也不使用 Demo 内置状态覆盖源表状态。

## 4. 第一阶段范围

### 4.1 允许读取

待办事项页面读取并展示：

- 任务记录 ID
- 任务事项
- 状态
- 负责人
- 板块
- 事项分类（源表存在时）
- 子分组（源表存在时）
- 备注（源表存在时）

除状态和负责人之外，其余字段在第一阶段均为只读。

### 4.2 允许更新

只允许更新：

- `状态`
- `负责人`

更新请求不得接受任务标题、板块、分类、备注或其他任意字段。后端必须使用字段白名单，而不能只依靠前端隐藏控件。

### 4.3 明确关闭

第一阶段关闭：

- 新增任务
- 删除任务
- 修改任务标题、板块、分类、子分组和备注
- 活动时间线新增、修改和删除
- AI 自动创建或直接修改任务
- 飞书通讯录读取
- 妙搭线上版本修改

核心数据、店铺诊断、公司目标和活动时间线继续保持现状；它们不属于本阶段的开发范围。

## 5. 状态与负责人选项

### 5.1 状态

- 状态选项以多维表格 `状态` 单选字段的字段配置为准。
- 工作台动态读取选项，不在代码中固定“待处理、进行中、已完成”等名称。
- 保存前必须确认所选值仍然存在于最新字段配置中。

### 5.2 负责人

- 负责人候选人从当前任务记录中已经解析成功的人员字段汇总。
- 使用飞书人员 ID 作为选项值，姓名只用于显示。
- 按人员 ID 去重，避免同名人员被错误合并。
- 没有出现在任务表中的新成员，第一阶段不能通过工作台分派。
- 不额外申请企业通讯录权限。

## 6. 页面与交互

### 6.1 默认视图

- 登录后默认显示“我的未完成任务”。
- “我的任务”通过当前飞书登录用户 ID 与负责人 ID 匹配。
- 页面保留“全部任务”入口。
- 如果当前用户没有匹配任务，显示明确的空状态，并提供查看全部任务的入口。

### 6.2 筛选与搜索

待办事项页面提供：

- 我的任务 / 全部任务切换
- 状态筛选
- 负责人筛选
- 板块筛选
- 任务关键词搜索

筛选默认在已读取的数据上执行；任务规模增长到影响性能时，再评估服务端分页和筛选。

### 6.3 任务详情与编辑

- 点击任务打开详情区域或抽屉。
- 任务标题、板块、分类、子分组和备注只读展示。
- 状态和负责人使用明确的选择控件编辑。
- 修改先保存在页面草稿中，不立即写入。
- 用户点击“保存修改”后才提交。
- 未发生变化时禁用保存按钮。
- 保存期间禁用重复提交。

## 7. 写入与复读验证

一次成功更新必须经过以下步骤：

1. 前端提交记录 ID、状态和负责人 ID。
2. 本地服务验证飞书登录会话。
3. 后端只提取允许更新的字段，并验证状态和人员 ID 来自当前可选集合。
4. 后端调用飞书多维表格更新记录接口。
5. 清除任务读取缓存。
6. 重新读取任务源表或目标记录。
7. 将读回的状态和负责人 ID 与提交值比较。
8. 完全一致时返回“已同步”；不一致时返回“待核对”，不能假装写入成功。

前端收到成功结果后刷新任务列表，并保持当前筛选条件。保存成功提示应包含最新状态和负责人，便于用户确认。

## 8. 错误处理

至少区分以下情况：

- 未登录或登录失效：提示重新使用飞书登录。
- 飞书应用缺少写权限：提示需要补充多维表格记录编辑权限。
- 状态选项已被源表管理员修改：刷新选项并要求用户重新选择。
- 负责人已失效或人员 ID 不可写：保留编辑草稿并提示重新选择。
- 目标记录不存在：提示任务可能已在源表删除，并刷新列表。
- 写入接口返回成功但复读不一致：显示“写入结果待核对”，不得显示“已同步”。
- 网络或飞书接口暂时失败：保留编辑草稿，允许用户重试。

面向用户的错误信息不显示 App Secret、访问令牌或完整接口响应。

## 9. 数据一致性与缓存

- 多维表格始终是最终事实来源。
- 前端不做乐观更新，不在飞书确认前永久改变任务显示值。
- 更新成功后清除所有任务读取缓存，包括匿名和已登录用户视角。
- 刷新后的列表必须来自真实读取结果，而不是仅合并本地提交内容。
- 第一阶段不引入独立数据库或离线写入队列。

## 10. 验收标准

第一阶段完成需同时满足：

1. 未登录时能读取任务，但无法更新。
2. 登录后能识别当前飞书用户。
3. 默认显示当前用户负责的未完成任务，并能切换到全部任务。
4. 状态选项来自多维表格字段配置。
5. 负责人选项来自已有任务中的真实人员 ID。
6. 前端只能编辑状态和负责人。
7. 后端拒绝其他任务字段的写入。
8. 新增和删除任务接口不可用。
9. 活动时间线写接口不可用。
10. 更新后能够从飞书重新读取并验证结果。
11. 写入失败或读回不一致时，不显示虚假的成功状态。
12. 自动化测试覆盖字段白名单、身份校验、缓存失效、复读一致和失败分支。
13. 最终进行一次受控的真实记录更新测试，并在验证后恢复原值；执行前明确选择测试记录并由用户确认。

## 11. 后续阶段

最小闭环稳定后，再分别设计：

1. 手动新增任务。
2. 任务删除或归档。
3. 活动时间线联动。
4. AI 异常识别与任务草稿。
5. 任务修改审计和分级权限。
6. 经营数据、AI 结论、任务执行和效果回看之间的完整闭环。

这些能力不提前混入第一阶段，避免无法判断问题来自任务写回、权限、AI 还是跨表关联。
