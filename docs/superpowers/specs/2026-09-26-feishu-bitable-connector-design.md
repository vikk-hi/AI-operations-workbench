# 飞书多维表格连接层设计

日期：2026-09-26  
项目：HM Operations Workbench

## 1. 目标

为本地 V2 工作台建立独立、可测试、可迁移的飞书多维表格连接层。第一阶段只读接通核心数据、待办事项、目标和活动时间线；后续在同一边界内增加受控的新增、修改和删除能力，使 AI 分析、异常识别、建议和人工确认后的联动都复用同一套数据接口。

妙搭线上版本和原始经营表在第一阶段保持不变。任何写入能力必须单独启用，不因只读连接完成而自动获得授权。

## 2. 已确认的数据分层

- 原始业务数据位于飞书多维表格。
- 妙搭 Dev/DataPaaS PostgreSQL 保存从多维表自动同步的副本。
- 当前妙搭后端通过 `DRIZZLE_DATABASE` 查询同步副本。
- 本地飞书 OAuth 已用于确认登录用户，但它不提供妙搭数据库连接。
- 本设计绕过妙搭 Dev 数据库，由本地后端通过飞书开放 API 连接指定多维表。

## 3. 总体架构

```text
飞书 OAuth ──────────────── 当前登录用户

飞书自建应用凭证
  └─ TokenProvider
      └─ BitableClient
          ├─ ReadRepository
          ├─ MutationRepository
          └─ AuditRepository
              └─ Workbench API (/api/workbench/*)
                  └─ V9 前端 / AI 分析 / 模块测试
```

身份与数据访问分离：用户 OAuth 用于界面身份和操作人记录；应用身份用于稳定访问明确授权的 Base。应用密钥和访问令牌只存在于本地后端，不传入浏览器。

首批连接以下已登记来源：

| 模块 | Base | 已知表 |
| --- | --- | --- |
| 核心经营数据 | `M1z2bWhVhahRlDsBUG1cDQUwnRg` | `tblxTrxDK5lGJxlo`；历史同期表需探测确认 |
| 执行任务 | `O4XhbiUw2aa5yRsgR8fckrNpnXe` | `tbl1Hi7UvvXTzTiQ` |
| 任务模板 / 活动时间线 | `KP2abpA8waP3Nbs3mptcXXMwn9d` | `tbl2bLwV4QSLDVYL`；模板表需探测确认 |

## 5. 连接组件

### 5.1 TokenProvider

- 使用服务端保存的 App ID/App Secret 获取应用访问令牌。
- 令牌仅保存在进程内存，按过期时间提前刷新。
- 不记录密钥、完整令牌或 Authorization 请求头。
- 后续如某张表必须使用用户身份访问，可增加用户令牌提供器，但不能静默扩大权限。

### 5.2 BitableClient

- 封装 Base 元数据、数据表、字段和记录 API。
- 统一处理分页、限流、超时、重试和飞书错误码。
- 只允许访问配置清单中的 Base/table；拒绝任意前端传入的目标 ID。
- 读取与写入方法分开导出，便于第一阶段彻底禁用写入。

### 5.3 Repository 与字段映射

- 每个业务模块拥有独立 Repository，把飞书字段转换为现有 Workbench API 契约。
- 原始记录必须保留 `record_id`、数据源、读取时间和必要的版本/更新时间信息。
- 日期、金额、人员、关联记录、多选和附件字段采用显式转换。
- 未识别字段进入诊断信息，不静默丢失或猜值。

### 5.4 Workbench API

继续提供现有接口：

- `/api/workbench/overview`
- `/api/workbench/tasks`
- `/api/workbench/targets`
- `/api/workbench/timeline`
- `/api/workbench/sources`

本地前端切换到本地 API；妙搭线上仍可使用原有后端。响应增加数据来源、最近读取时间、连接模式和警告信息，不改变主要页面结构。

## 6. 读取策略

- 第一阶段只申请和使用多维表只读权限。
- 初次连接先读取 Base/table/field 元数据，再生成或确认字段映射。
- 记录查询完整处理分页，不把第一页误认为全量数据。
- 服务端设置短时缓存，避免同一页面并发重复读取。
- 页面展示“最近成功读取时间”，不能把缓存结果描述为实时同步。
- 单表失败时返回模块级错误，不阻断其他已成功模块。

## 7. 新增与修改设计

写入能力默认关闭，并按表配置权限矩阵：

| 数据类型 | 读取 | 新增 | 修改 | 删除 |
| --- | --- | --- | --- | --- |
| 原始经营数据 | 允许 | 禁止 | 禁止 | 禁止 |
| 公司历史目标 | 允许 | 默认禁止 | 默认禁止 | 禁止 |
| 品牌目标副本 | 允许 | 可单独启用 | 可单独启用 | 默认软删除 |
| 执行任务副本 | 允许 | 可单独启用 | 可单独启用 | 取消/归档 |
| 活动时间线副本 | 允许 | 可单独启用 | 可单独启用 | 默认软删除 |

所有新增和修改遵循：

1. 前端或 AI 生成变更草稿。
2. 后端校验目标 Base/table、字段白名单、类型和必填项。
3. 返回变更预览，展示目标记录、修改前和修改后。
4. 用户明确确认后执行一次写入。
5. 后端返回真实飞书结果并记录审计信息。

新增操作使用幂等键，避免重复创建。修改前重新读取目标记录；如果更新时间或关键字段已经改变，停止覆盖并要求用户重新审阅。

## 8. 删除策略

- 默认禁止物理删除。
- 业务删除优先转换为“已取消”“已归档”或专用软删除字段。
- 只有配置清单明确列出的临时副本表可以启用物理删除。
- 物理删除必须展示 Base、table、record ID、记录标题和影响数量，并进行二次确认。
- 批量删除不与普通修改共用确认按钮。
- 删除结果进入审计记录；失败记录逐条返回，不假装整批成功。

## 9. AI 联动边界

- AI 可以读取经过权限过滤的数据并生成结论、异常和行动建议。
- 每条关键结论应保留证据：数据源、记录范围、筛选条件、指标公式和截止时间。
- AI 只能生成新增/修改/删除草稿，不能自行提交。
- 用户确认页必须展示目标表、记录、字段差异和预计影响。
- 写入权限关闭时，AI 仍可输出建议，但界面不得显示为已执行。

## 10. 安全与配置

- `.env.local` 继续被 Git 忽略。
- App Secret、用户访问令牌和刷新令牌不得进入日志、测试夹具、浏览器存储或错误响应。
- 数据源清单可提交，但只能包含 Base/table ID、别名、字段映射和权限策略，不包含凭证。
- 服务端仅监听本机地址；未来部署时重新配置 HTTPS、Cookie 和密钥管理。
- 当前已在聊天中出现过的 App Secret 应在联调完成后轮换。

## 11. 错误处理与可观察性

- 区分未授权、表未共享、字段变更、限流、网络失败和数据为空。
- 日志只记录请求类型、数据源别名、耗时、页数、记录数和飞书错误码。
- 页面显示模块级连接状态和最近成功读取时间。
- 字段漂移检测失败时停止对应模块写入，但不影响其他只读模块。

## 12. 测试与验收

### 自动测试

- Token 缓存与刷新测试。
- 分页、限流和错误映射测试。
- 每个 Repository 的字段转换测试。
- Workbench API 契约测试。
- 写入权限矩阵与字段白名单测试。
- 幂等新增、冲突修改、软删除和物理删除保护测试。
- 密钥及令牌不进入响应或日志的测试。

### 真实只读冒烟测试

- 读取已授权 Base 元数据。
- 获取每个目标表的字段定义和少量样本记录。
- 分页读取记录总数并与飞书页面可见范围核对。
- 验证核心数据和待办页面显示真实来源与读取时间。
- 不执行新增、修改或删除。

### 第一阶段验收标准

- 本地飞书登录继续有效。
- 核心数据、待办事项、目标和时间线至少三个真实模块成功读取；任何未接通模块显示准确原因。
- 页面不再依赖妙搭 `DRIZZLE_DATABASE` 才能展示真实数据。
- 原始表无新增、修改或删除记录。
- 测试、类型检查和前端构建通过。

## 13. 实施顺序

1. 权限与数据源元数据探测。
2. TokenProvider 和只读 BitableClient。
3. 核心经营 Repository 与 API。
4. 执行任务 Repository 与 API。
5. 目标、模板和时间线 Repository。
6. 前端本地 API 切换、状态与来源展示。
7. 真实只读冒烟测试。
8. 第一阶段验收后，再分别设计并启用新增、修改和删除权限。

## 14. 非目标

- 第一阶段不发布或修改妙搭线上版本。
- 第一阶段不启用多维表格写入权限。
- 不提取或绕过妙搭内部数据库凭证。
- 不把原始经营数据复制为另一套长期主数据。
- 不把 AI 建议自动转换为已执行操作。
