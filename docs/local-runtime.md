# Local V9 runtime

## 启动方式

安装锁定依赖后运行：

```bash
npm ci
npm run dev:local:web
```

打开 `http://127.0.0.1:8080/client/index.html`。本地身份与数据 API 监听 `127.0.0.1:3001`。

`.env.local` 只需保存在项目根目录，包含本机的 `FEISHU_APP_ID` 和 `FEISHU_APP_SECRET`。该文件被 Git 忽略。

## 数据来源

本地页面在 `localhost` 或 `127.0.0.1` 下使用本地 `/api/workbench/*`：

- 核心经营数据：2026 天猫日报
- 待办事项：工作日报任务
- 公司目标：QM 目标
- 活动时间线：大促 TIMELINE

线上妙搭页面继续使用原有 `axiosForBackend`；本次读写联动仅在本地运行时启用。

## 权限边界

- 核心经营数据、公司目标和活动时间线保持只读。
- 待办事项可匿名读取；只有完成飞书登录后，才能修改已有任务的 `状态` 和 `负责人`。
- 服务端只接受 `PATCH /api/workbench/tasks/:recordId`，并只接受 `status`、`responsibleOpenIds` 两个字段。任务新增/删除、时间线写入及其他模块写入均返回 `405`。
- 状态值实时取自任务表“状态”单选字段的元数据；负责人候选只取当前任务记录中已出现的飞书人员 ID，不按同名合并。
- 写入完成后，服务端会重新读取同一条多维表格记录。只有回读的状态和负责人完全一致，页面才显示同步成功；不一致返回 `409` 并保留编辑窗口。
- 页面请求失败时显示模块错误，不回退成伪造的真实数据。
- App Secret、访问令牌和记录字段值不会写入探针报告。
- 聊天中曾出现过的 App Secret 应在本次联调完成后轮换。

## 真实记录验证流程

1. 打开 `http://127.0.0.1:8080/client/index.html` 并完成飞书登录。
2. 在“待办事项”中确认默认视图为“我的未完成”，打开一条任务详情。
3. 记录任务的 record ID、标题、原状态和原负责人，并明确选定一个可恢复的临时变化。
4. 经业务人员确认该条记录后保存修改；看到“已与多维表格同步”仅代表服务端已经完成新鲜回读核对。
5. 再次打开同一任务确认值一致，然后恢复原值并再次核对。

不要用生产记录做未经确认的试写。验证过程中不需要、也不应在终端或文档中输出 App Secret、访问令牌或完整业务记录。

2026-09-26 已对一条经业务人员明确批准的测试记录完成闭环验收：原状态 → 临时状态 → 原状态。两次保存均由服务端重新读取同一记录核对，最终状态和负责人已恢复；文档不保留该记录的业务内容。

## 验证

```bash
npm test
node --experimental-strip-types --test tests/*.test.ts
npm run type:check:client
npm run build:client
npm run verify:bitable
```

`verify:bitable` 会完整处理分页，但只输出每个来源的字段数和记录数，不输出记录内容。
